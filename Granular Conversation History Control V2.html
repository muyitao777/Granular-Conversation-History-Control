Ideal state — V2, the layered end-state

From the proposal's recommendation: context is scoped to the current issue by default (Option 1), a sensitivity check decides when the card appears (Option 2), and admins set defaults by field and PII type (Option 3). The card becomes rare — and stays meaningful.

How the layers fit together

No single option is enough on its own: smart filtering can guess wrong, a popup shown every time gets ignored, and admin rules can't tell what's actually inside a conversation. So each option gets one job — and each one backs up another.

OPTION 1
The default layer
topic-scoped context

Every handoff sends only a short summary of the current issue — the VPN request never includes the earlier HR conversation. No extra clicks, cleaner context; but it's an AI guess, so it's never trusted on its own.

OPTION 2
The safety net
consent / preview

Flash checks whether anything in the outgoing summary looks sensitive. Only then — or when admin rules require it — does the confirmation card appear. The user is the only one who knows what's private to them, and because the card shows up rarely, people actually read it.

OPTION 3
The control plane
admin policy

Admins set a rule for each type of field and PII: always share it, ask the user first, or never send it. Simple rules that can be checked and audited — the rules decide when info can move; the other layers decide what gets sent.

How they work together — one handoff through the stack

The steps run in order, and each one can only remove information — never add it. First, Flash trims the conversation to a summary of the current issue (Option 1) — that's the most that can ever be shared. Next, the admin rules (Option 3) remove anything marked "never send" and flag anything marked "ask first". Finally, if what's left still looks sensitive — or the rules require it — the card appears (Option 2) and the user decides. The agent only sees what made it through all three.

Each step also catches the mistakes of the one before it: if the summary accidentally includes an HR line, the sensitivity check flags it and the card shows it to the user; if the check misses it too, the "never send" rules still block those fields. That's why the card can stay rare and still be safe — and the same steps run before both tickets and live-agent chats.
